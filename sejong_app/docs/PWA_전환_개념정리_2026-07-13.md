# sejong_app WebView앱 → PWA 전환 개념정리 (2026-07-13)

> 세종시 혈당관리 실증앱(`sejong_app`, JSP/eGov/Apache Tiles)을 **네이티브 WebView 앱(APK) → PWA** 로 전환하기 위한 개념·구현·한계 정리.
> "웹을 앱처럼" 쓰되, 네이티브가 하던 일을 웹으로 옮기고 못 옮기는 건 폴백으로 메꾸는 것이 핵심.
> **현 상태**: PWA 골격 커밋됨 + 이번 세션에 카카오/저장/하단네비 전환분 반영. 블루투스·푸시는 향후 필요 시 폴백으로 대응(아직 미구현).

---

## 1. PWA란 — WebView 앱과의 차이

| | WebView 앱 (지금까지) | PWA (전환 방향) |
|---|---|---|
| 정체 | 네이티브 앱 안에 웹을 담는 껍데기(WebView) | 웹사이트를 "홈에 설치"해 앱처럼 쓰는 것 |
| 실행 엔진 | 앱이 만든 WebView | **폰 브라우저**(안드로이드=크롬, iOS=사파리) |
| 네이티브 코드 | 필요(WebViewClient, 스킴처리, 브리지 등 직접 작성) | **없음** — 브라우저가 대신 |
| 설치 | 플레이스토어 APK | 브라우저 "홈 화면에 추가" |
| iOS | App Store 등록 필요(심사) | 사파리 홈추가로 동일하게 |
| 업데이트 | 새 APK 재배포/재설치 | 웹만 고치면 자동 반영 |

---

## 2. 왜 PWA로 가는가 (sejong_app 맥락)

- **iOS 설치 문제 해결** — APK는 안드로이드 전용이라 아이폰 설치 불가. PWA면 URL/QR 하나로 iOS·안드로이드 통일.
- **배포·업데이트 간소화** — APK 빌드·서명·QR 재설치가 사라지고 웹만 고치면 자동 반영.
- **네이티브 의존이 거의 없음** — 실제 쓰는 `callAndroid` 브리지는 `f101/f102`(자동로그인·번호저장)뿐. 걸음·수면·혈당은 외부 클라우드 API로 수신.
- **카카오 로그인도 덤으로 해결** — 브라우저가 카카오톡 스킴을 알아서 처리 → WebView의 "앱 갔다 안 돌아옴" 문제 소멸.

## 3. 이미 구축된 PWA 구성요소 (어제 커밋됨) — 상세

### 3-1. `manifest.webmanifest` (webapp 루트) — 설치 정보
브라우저가 "설치형 앱"으로 인식하게 하는 명세.

| 항목 | 값 |
|---|---|
| name / short_name | `연속혈당 allCare` / `allCare` |
| start_url | `loginPage.do` (실행 시 로그인 화면으로 시작) |
| scope | `./` |
| display / orientation | `standalone` / `portrait`(세로 고정) |
| theme_color / background_color | `#005b8e` / `#ffffff` |
| icons | `icon-192`(any) · `icon-512`(any) · `icon-maskable-512`(maskable) |

### 3-2. `sw.js` (webapp 루트) — 서비스워커 / 캐시 전략
백그라운드에서 요청을 가로채 캐시 관리. 설치 가능 조건 충족 + 오프라인 폴백 제공.

| 요청 종류 | 전략 |
|---|---|
| HTML · `.do` · `.jsp` · navigation | **항상 네트워크** (실패 시 `offline.html`) → 화면은 항상 최신 |
| CSS · JS | **network-first** → 배포/수정 즉시 반영(옛 CSS 계속 뜨던 문제 방지) |
| 이미지 · 폰트 (`<BASE>/asset/`) | **stale-while-revalidate** → 빠르게 뜨고 뒤에서 갱신 |
| 그 외(외부 CDN 등) | 미처리(브라우저 기본) |

- **캐시 버전**: `allcare-static-v2` — 배포 후 정적캐시를 강제 갱신하려면 이 값을 올린다(예: `v2` → `v3`).
- **BASE 자동감지**: `sw.js` 위치에서 유도(`/app/sw.js` → `/app/`) → 루트든 컨텍스트 경로든 코드 수정 없이 동작.
- `install` 시 `skipWaiting()`, `activate` 시 옛 캐시 삭제 + `clients.claim()`.

### 3-3. `WEB-INF/inc/pwa-head.jsp` — 모든 `<head>`에 삽입
레이아웃(`tiles/login/login.jsp`, `tiles/main/main.jsp`)의 `<head>`에서 static include.

- `<link rel="manifest">`, `<meta name="theme-color" content="#005b8e">`
- 아이콘: `rel="icon"`(192), `rel="apple-touch-icon"`
- iOS 메타: `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `apple-mobile-web-app-title="allCare"`
- **서비스워커 등록**: `navigator.serviceWorker.register('<컨텍스트>/sw.js', {scope:'<컨텍스트>/'})` — https/localhost에서만 동작.

### 3-4. 아이콘 · 설치 QR (`asset/images/pwa/`)
- `icon-192.png`, `icon-512.png` — 일반 아이콘
- `icon-maskable-512.png` — **안드로이드 적응형**(둥근/각진 마스크) 대응
- `apple-touch-icon.png` — **iOS 홈 아이콘**
- `install-qr.png` / `install-qr.svg` — 설치 안내용 QR (이미 준비돼 있음)

### 3-5. `offline.html` (webapp 루트) — 오프라인 폴백
네트워크가 끊겨 화면(.do/.jsp)을 못 받을 때 `sw.js`가 대신 띄우는 페이지. 서비스워커 프리캐시에 포함.

### 3-6. HTTPS — 필수 전제조건
서비스워커·설치·푸시는 **https(또는 localhost)에서만** 동작. http로 서비스하면 위 전부 무효 → 운영 도메인이 https여야 PWA 성립.

## 4. 이번 세션에 전환·수정한 것 (커밋 `5ce1bb3` + footer.jsp 후속)

| 구분 | 파일 | 내용 |
|---|---|---|
| **저장(네이티브→웹)** | `asset/js/app-common.js` | 브라우저 폴백에서 `f102`=localStorage 저장, `f101`=저장값을 `userInfoCallBack`으로 전달. login.jsp·setting.jsp·login_back.jsp 일괄 적용. **WebView 앱도 그대로 동작**(폴백 방식이라 되돌릴 필요 없음) |
| **뒤로가기 종료** | (동일) `f100` | PWA엔 "앱 종료" 개념 없음 → 브라우저 폴백 no-op(크래시 없음). `appBackButton`은 네이티브 back에서만 호출돼 PWA에선 미동작 |
| **카카오 로그인** | `WEB-INF/jsp/login/login.jsp` | ① 비동기 `getStatusInfo` 콜백 안에서 `login`을 부르던 걸 **클릭 흐름에서 직접 호출**(모바일 팝업차단 해결) ② SDK init `try` 방어 ③ `throughTalk:false`(브라우저 내 로그인 → 복귀 안정) ④ `/v2/user/me` 실패 시 **토큰 비우고 1회 재로그인 복구 + 실제 에러 노출** |
| **하단 공통 네비(선택표시)** | `WEB-INF/tiles/main/footer.jsp` | 현재 섹션 탭에 `class="on"`. **URI가 Tiles include에서 템플릿 경로로 잡히는 문제** → 컨트롤러의 `menuName`으로 판정. **우선순위 운동→식사→혈당**(`식사연관 혈당분석`·`운동연관 혈당분석`처럼 이름에 '혈당' 겹쳐 중복강조 방지) |
| **대시보드 홈탭** | `WEB-INF/jsp/login/main.jsp` | 홈 탭 `class="on"` |
| **하단 네비 스타일** | `asset/css/common.css` | `env(safe-area-inset-bottom)` 여백(홈 인디케이터 가림 해소), 터치영역 확대(min-height 48px, 음수마진 제거), `:active`/`.on` 선택표시(파란 배경+파란 굵은 글씨) |

## 5. 네이티브 기능 한계 & 폴백 (향후 참고)

> PWA가 못 하는 게 있어도 앱 전체를 되돌릴 필요는 없다 — 막히는 기능만 골라 보완.

| 기능 | 안드로이드 PWA | iOS PWA | 문제되면 |
|---|---|---|---|
| **푸시 알림** | ✅ 지원 | △ 조건부(16.4+ · 홈설치 · 허용) | **SMS/카카오 알림톡**(기존 NCP SENS `sendSensApi.do` 재활용). 중요 건강알림은 SMS 병행 권장 |
| **블루투스(BLE 직접연결)** | ✅ Web Bluetooth | ❌ 완전 미지원(애플 하드차단) | ①벤더 클라우드 경유 ②iOS만 얇은 네이티브 래퍼(하이브리드) |
| **걸음·수면·혈당센서** | ✅ (외부 API) | ✅ (외부 API) | 지금처럼 클라우드 API 수신(i-Sens `cgm.i-sens.com`, `getBloodData.do`) |
| **자동로그인·번호저장** | ✅ | ✅ | localStorage 폴백 (완료) |
| **카메라(음식사진)** | ✅ | ✅ | `<input capture>` |
| **설치/배포** | ✅ 홈추가 | ✅ 홈추가 | URL/QR 하나로 통일 |

### 판단선 — 딱 하나만 보면 됨
**"폰이 기기에 *직접* BLE로 연결하나?"**
- **아니오(클라우드 경유)** → PWA로 끝. (현재 혈당 구조가 이것)
- **예(iOS 필요)** → 그 부분만 하이브리드/클라우드 경유, 나머진 PWA.

## 6. 배포 방식의 변화

| | 전 — APK | 후 — PWA |
|---|---|---|
| 만드는 것 | APK 빌드(서명) | 웹 배포 |
| QR이 가리키는 것 | APK 다운로드 링크 | 웹 URL |
| 설치 | APK 설치(출처불명 허용) / iOS 불가 | 브라우저 "홈에 추가"(iOS·안드 공통) |
| 업데이트 | 새 APK 재설치 | 웹만 고치면 자동 |

## 7. 되돌리기 & 남은 구조 이슈

### 복구는 쉬움
- Git 커밋 단위 복원.
- PWA 파일(manifest/sw.js)은 "추가물" → 삭제하면 원상복구.
- `f101/f102`는 폴백 방식이라 **WebView 앱과 동시 생존**(되돌릴 필요 없음).
- 서비스워커 걷어낼 땐 **kill-switch SW**(스스로 unregister + 캐시삭제)로 남은 기기까지 정리.

### 구조적 잔여 이슈 (강조 실패와는 무관, 별도 정리 대상)
- **푸터가 2벌 중복**: 대시보드(`login/main.jsp` 인라인) + 공통(`tiles/main/footer.jsp`). 언젠가 공통 1벌로 통일 권장.
- **푸터가 `</html>` 밖에 렌더**: 콘텐츠 페이지(FAHR_00.jsp 등)가 자기 `</body></html>`를 닫아 tiles 푸터가 문서 밖으로 밀려남. CSS 강조엔 무관하나 스크롤·고정 등 레이아웃 취약점.

## 8. 실무 팁

- **정적파일 배포 후에도 옛 캐시가 남으면** → `sw.js`의 `CACHE_VERSION`을 올린다(`v2`→`v3`).
- **JSP 수정이 로컬에서 안 보이면** → 톰캣 재시작 / work 디렉터리 캐시 삭제(옛 컴파일본 사용 방지).
- **카카오 "로그인 후 안 돌아옴"이 남으면** → Kakao Developers 콘솔에서 **플랫폼>Web에 서비스 도메인(https) 등록**, 카카오 로그인 활성화 + 동의항목(이메일) 확인.
- **배포는 파일 반영 방식**(git 커밋만으론 서버에 안 올라감) — 변경 파일을 서버에 직접 반영해야 함.

## 9. [2026-08-25] display: fullscreen → standalone (하단 시스템 네비게이션 가림 해결)

- **증상**: 안드로이드에서 앱이 시스템 네비게이션 바를 덮음. 하단을 스와이프하면 바가 잠깐 나타났다가 자동으로 사라짐. "PWA 전환 전에는 있었다."
- **원인**: manifest 의 `"display": "fullscreen"` — 설치형 PWA 를 **몰입(immersive) 모드**로 띄워 상태바·네비게이션 바를 숨긴다. 스와이프 시 일시 표시 후 자동 숨김이 이 모드의 정의된 동작.
- **조치**: `"display": "standalone"` 으로 변경 — 브라우저 UI(주소창) 없는 앱 모양은 유지하면서 시스템 상태바·네비게이션 바는 항상 표시.
- **⚠전파**: display 모드는 **설치 시점에 굳는다.** 서버에 반영해도 이미 설치된 기기는 크롬이 매니페스트 갱신을 확인할 때까지(수일) 옛 모드로 남을 수 있다 → 즉시 확인하려면 **홈 화면 아이콘 삭제 후 재설치**.
- 같은 날 viewport 에 `viewport-fit=cover` 도 추가(tiles 3벌) — 하단 탭(.footerNav)의 env(safe-area-inset-bottom) 여백이 이제야 발동한다. standalone 으로 바가 항상 보이면 이 여백은 0이 되어 부작용 없음.
